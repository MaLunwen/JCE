# tools/lint — public source gates

The component roundtrip field gate follows component-typed helper calls from
the actual parse/serialize root functions and their quoted same-directory
private include closure. Uncalled helpers and reflection accessors never prove
persistence. Parse-default reads cannot satisfy the independent serializer
write direction. Missing helpers fail closed. The actual-source Python controls in
tools/tests/test_component_serializer_helpers.py omit each real colour read,
the real writer, the real call or the included helper, and retain an uncalled
typed accessor as a negative control.
These are lexical direction checks; the real Scene/native component fixture
owns byte/value roundtrip and shared-parser missing-read controls.

Desktop JNI now belongs to Application. The layer gate has no former Platform
exceptions for its application headers; moving the actual host, not adding an
exception or raising a baseline, removes that reverse include edge.

The public source aggregate explicitly executes stock-app producer/sealer,
typed renderer-submission and screenshot-request ledger controls under tools/tests.
These Python controls are distinct from the stock consumer's eight native CPU
checks and actual Editor/EXE/Bundle runs. Registered files are not pass evidence.

run_all.py defaults its failure transcript to build/reports/lint-failure.txt.
Its existing failure-write/success-clear lifecycle applies only to that current
path; legacy reports/ history is not migrated or cleared. The prospective
layout is contracts/build-output-layout.md. Actual Python path/log controls
live in tools/tests/test_generated_output_defaults.py and run in this aggregate.

run_all.py aggregates independent public gates. Private workflow suites are
optional local additions and must be reported as unavailable when absent.
The actual Game View resolver/selection controls and the consumer probe
artifact/trace-validator controls are part of that public source aggregation.
Their CPU results do not certify physical UI input or actual GPU transfers.
Checks inspect the real staged tree, enforce maintained contracts and need a
negative control when introduced. Never weaken a failing check or refresh a
baseline merely to make it green. No build recipe or user-project generation
belongs here. Source layout is declared by contracts/source-layout.json.

`lint_git_files.working_tree()` subtracts only `git ls-files --deleted` from
the existing cached/untracked-not-ignored inventory, so an unstaged source move
does not leave a stale reader path. `tracked()` keeps its original baseline
semantics. Other missing or unreadable admitted sources remain failures; no
filesystem-existence skip or path exemption is introduced. Existing view-name
arity/sentinel and authored-path consumption rules still inspect the moved
untracked owner. Real temporary-Git migration/ignored/read-refusal controls are
in `tools/tests/test_bgfx_view_name_length.py`; they do not stage the product.
Its optional strict mode uses NUL-delimited UTF-8 paths and raises on either
Git command/launch failure. The default working_tree() and tracked() retain
their legacy behavior. Singleton inventory explicitly selects strict mode so
unavailable source discovery cannot lower its mutable-state count.
The Conan source-policy AST gate allows only an unaliased `import shlex` used
directly as `shlex.split` on literal text or a literal-string join, with literal
boolean parsing options. Lexer streams/source hooks, module attributes, aliases,
import-from, shadowing, loaders and filesystem operations remain refused.
Existing dependency-file/callback and code-bypass guards remain active; module
introspection is also refused. Its self-check and actual hook controls in
test_conan_configuration.py include ordinary blanket-import and unrestricted-
module mutations. This syntax guard is not a Python security sandbox and does
not certify upstream source purity or actual package compilation. Installed hook
comparison uses conan_config.select_hook_home, the native builder's read-only
policy. An explicit CONAN_HOME remains strict; a default-home conflict selects
the existing owned tuple without creating or repairing it. Check actual selected
bytes and retain retired-source-hook refusal. Missing planned hooks are not an
executed-build certificate; never claim the ignored original hooks were repaired.
Actual temporary-filesystem controls in test_conan_config.py preserve original
bytes/mtime, reject explicit/managed stale hooks and exercise changed tuples.
The shipped-main declaration gate recognizes static and JCE_INLINE definitions
without treating bare calls as declarations; negative callee controls live in
tools/tests/test_shipped_main_declarations.py.

The shader varying gate requires the complete declared IO interface for every
linked pair, including shared vertex stages. Unused fragment varyings remain
part of the bgfx link hash. Shared-stage mismatches have a failing control.

CTest closure scans use `lint_git_files.working_tree()` so ignored build/frozen
copies cannot become source declarations. Verified jce_add_unit_test/cxx_test
providers close their target dependency for additional raw CTest cases; literal
raw targets without either provider or explicit dependency still fail. Controls:
`tools/tests/test_jce_tests_closure.py`, including actual Git-ignore enumeration.

The self-test caller gate uses the same maintained working-tree authority and
one invocation-local index: every eligible C/C++ source is read and comment
stripped once, then shared by all defined self-test symbols. Ignored generated
callers and vendor source cannot prove consumption. Missing or unreadable source
reports UNAVAILABLE; stale exemptions still fail. Matching remains lexical,
including the existing external-declaration/string behavior, and does not prove
test execution. Controls live in `tools/tests/test_self_tests_run.py`.

Editor-consumption exemptions must name the real product owner and why the
Editor uses a different supported entry, rather than increasing the baseline
or adding an unused panel call. jce_fs_probe_read belongs to the Runtime
implicit mixer-config resolution in jce_rt_audio.c; Editor Play supplies the
explicit path authored by its Audio Mixer panel. The exemption does not claim
a direct Editor metadata probe or actual runtime execution from lexical hits.
