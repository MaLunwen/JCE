# reason later" fails closed instead of silently passing.

# THE PATTERN THESE ENTRIES SHARE (2026-08-26 audit of the two 0.0% umbrellas)
#
# The editor authors DATA; an engine system calls the API.  Two shapes:
#
#   (1) ECS component -- the editor registers a component in
#       jce_editor_component_registry.cpp, serialises it into the scene, and a
#       world/runtime system consumes it.  Evidence for triggers:
#       engine/src/middleware/world/jce_world_ecs.c declares
#       ECS_COMPONENT_DECLARE(JceTriggerVolumeEcs) / (JceTriggerObserverEcs).
#
#   (2) settings struct -- the editor writes fields of
#       JceSceneRenderingSettings and the scene renderer drives them per frame.
#       Evidence for weather: jce_panel_lighting_settings.cpp's own comment
#       names sr_drive_time_of_day / sr_drive_weather as the consumers.
#
# In both shapes a direct editor call would create a SECOND owner of state the
# runtime already owns, which is the defect these entries prevent -- not a
# gap.  That is why they are exempt rather than "to be wired".
#
# NOT exempt, deliberately: jce_road_network_* (14 symbols).  Repo-wide it is
# reachable only from engine/src/middleware/world/jce_spawn_manager.c, its own
# .c and its header; "Road" has zero hits under editor/src, and no user project
# calls it either.  That is built-but-unwired debt, and exempting it would hide
# exactly the thing this gate exists to show.
# ---------------------------------------------------------------------------

Its product consumer is rt_init_mixer (jce_rt_audio.c), which walks jce_audio_mixer_send_count/_send_at for every mirrored bus at Play start and passes jce_audio_mixer_resolve_send's value -- so the send obeys the same mute and solo the direct path does. The capability IS exposed to authors, as the per-bus send rows in the audio mixer panel (jce_panel_audio_mixer.cpp:180, :754, :773), which is where the amount is edited and from where audio_mixer.json is written; it reaches the device through the runtime. An editor caller would be routing the LIVE graph behind the authored config's back, so what an author saved and what is sounding would differ with nothing reporting it.
jce_audio_bus_get_send  # The read half of the setter above and useless without it; if that line ever goes, this one goes with it. It reports the DEVICE's current send, which during Play is the resolved value (source volume folded in, 0 when muted) rather than the authored amount -- so a panel displaying it would show a number that disagrees with the slider the author is holding. The authored value is the mixer's, via jce_audio_mixer_get_send, and that is what the panel already reads. Its product consumer is the device test, which uses it to prove the send survives a later insert chain.
jce_audio_load_streaming  # Keeps a clip's ENCODED bytes resident and decodes per voice on demand, instead of one up-front decode into s16. Its product consumer is rt_spawn_audio_source (jce_rt_audio.c), which calls it when the authored JceAudioSourceComponent.load_type says STREAMING. The capability IS exposed to authors, as the Load Type combo on the AudioSource inspector; it reaches the device through the runtime. An editor caller would be choosing residency for a clip behind the component's back, so what an author saved and what is resident would differ with nothing reporting it -- and the editor's own audition goes through jce_runtime_audio_play precisely so what it hears is what the shipped game does.
jce_console_cmd_count  # The command half of the registry's enumeration, added as the companion to jce_cvar_count()/jce_cvar_at() so that a completion key cannot know half the namespace -- before it, commands could be registered and dispatched but never listed, and the built-in `help`/`list` were an if-branch inside jce_console_exec rather than table entries, so they worked without existing.  Its product consumer is JceConsoleSession (engine/src/os/core/jce_console_session.c), which walks cvars and commands together for Tab completion, and the editor's console panel reaches it THROUGH that session -- the panel's Tab key lists matches from jce_console_session_match_at, which is the accessor one layer up and is consumed.  A direct editor caller would be a second implementation of `help`, which now walks this same table; duplicating it in the panel is the defect this commit removed from that file, not one to reintroduce.
jce_console_cmd_at  # The accessor half of the pair above, exempt for the same reason and listed separately so that removing one does not silently carry the other.  It is also the only way to read a command's help text, which the engine's `help` command uses when it prints the table -- so its output IS visible in the editor console, routed through the sink the panel installs.  The capability is exposed to the author as `help` and as the Tab key, not as a C call the panel makes.
