# Platform CPU controls

Follow tests/AGENTS.md. The single-instance identity fixture consumes the full
actual Windows lock/publication/activation owner with counted native ports and
strict extracts of the Engine's rejection branch and complete shared constructor
failure tail. It uses the public JceAppResult and typed quit/destroy ports; the
minimal Engine shape supplies only fields accessed by those extracts. The port
models cleanup acceptance/refusal, never real SDL shutdown or heap retirement.
Assertions retain PID identity, native attention admission, DIST-visible logs,
lock ownership and bypass behavior, and additionally verify the failed result,
released constructor borrow, same-owner cleanup delegation and retained owner
when that dependency refuses. Complete Engine cleanup proof belongs to the
application fixtures. Do not restore the obsolete direct SDL_Quit/free path just
to make this extraction compile.

The old_pid control changes only the complete actual platform owner's PID
comparison. It must compile and fail ordinary unchanged identity assertions;
configuration/compilation failure is not accepted negative evidence. Generated
extracts use the shared write-if-changed helper and tracked source dependencies.
These controls do not activate windows or establish actual foreground focus.

The existing real input-record roundtrip fixture also checks the canonical
current-snapshot origin: capture retains it, update/ordinary apply/refusal/live
ingestion clear it, and EOF withdraws it even without an intervening update.
Only real record/open/replay functions create a replayed state. The complete
recorder stale-origin mutation omits its per-attempt reset and must compile
then fail ordinary unchanged assertions; WILL_FAIL alone is insufficient.
These tests use public host IO and no physical device/window.
