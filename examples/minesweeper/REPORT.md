# 扫雷示例验证报告

2026-09-22，Windows x64，安装 SDK，Direct3D 11，Ollama qwen3.5:0.8b。引擎和编辑器仅作为公共 SDK、CLI 与程序被消费。

## 已完成实践

- 标准 cook + 编辑器 headless build-project 构建、打包成功。
- 实际 SDK 可执行文件通过 3000 个随机种子棋盘规则检查：布雷数量与唯一性、首格八邻域保护、数字、边角、Flood Fill、旗帜、胜负、计时和重置。
- 真实键鼠回放验证初／中／高级、翻格、插旗／取消、旗帜保护、踩雷失败、无旗胜利、最佳时间写入。
- 截图检查菜单、数字、爆炸格红底、所有雷、错误旗帜 X，以及编辑器 Game View。
- 编辑器 Play 加载同一个 C 模块与 Lua 驱动，并通过键盘开始棋盘；会话文件测试后逐字节恢复。
- 四协议 × 文本／图片／受限数值 = 12 项实测通过；另有 7 项非法参数拒绝检查。
- 真实游戏 AI REMIX：提交后约 0.8 秒得到 10×10／12 雷与绿色配色，Lua 发布 revision=2，随后自定义棋盘实际使用这些数值。

## 通用问题与用户侧处理

| 问题 | 实测或定位证据 | 本例处理 |
|---|---|---|
| build-project 沿用旧 cooked 场景 | 编译成功、startup loaded，但 Canvas=0，cooked 仍为空场景 | 明确先运行 cook |
| UIButton 状态覆盖遮挡 UIText | ui_canvas 状态阶段在文本后重画整个矩形；白屏／无文字截图 | 状态色 alpha=0，UIImage 管底色；没有修改引擎 |
| design 把未知字段只作为警告 | 模型返回 Transform.pos，仍打印 OK | 拒绝该输出；使用六整数严格验证的配置任务 |
| 批量 entity.create 偶发文件打开 Errno 22 | automation serialize.py 写入调用两次报错 | 检查已落盘实体再继续；示例生成器支持场景封装，按名称跳过已存在实体 |
| 回环请求被代理转发 | 网关未运行时代理给出空 502，直接请求显示连接拒绝 | NO_PROXY 加入回环地址；先检查网关健康 |
| Gemini REST 字段兼容 | 旧 snake_case 与网关不匹配 | AI CLI 改用 systemInstruction / inlineData / mimeType |

## 待验证或尚未接通

- 编辑器 Play 的 AI REMIX 子进程连接与持久成绩，当前只接在独立程序 SDK 入口；按钮在编辑器里仅产生命令。
- 编辑器右／中键与独立程序不保证一致；可通过 F 模式使用左键插旗。尚未做完整输入、像素一致性比较。
- 中键 chord 的完整真实交互验收、跨平台、长期压力、缩放／高 DPI 及中文 UI 尚未覆盖。
- 没有给当前模型添加搜索、工具调用或远程资产下载功能；没有把四协议当成四家真实云模型测试。
- 原生示例业务规则仍为项目 C 代码；它展示数据和组件结合，不宣称整个游戏由 0.8B 模型自动生成。

## 2026-09-23 编辑器鼠标捕获修复

Game View 原先仅对有活动 VCam 的无角色场景禁用 FPS 捕获；扫雷的普通 Camera + Canvas 场景仍会在左键点击时锁定鼠标。现改为 Play / Pause 中仅角色控制器场景允许该捕获，并在应用失焦时清除捕获意图；无角色场景也不再显示点击进入飞行的提示。修改限于编辑器 Game View，未改引擎。

编辑器构建、88/88 lint 和扫雷编辑器 Play 自动回归通过；会话文件已恢复。computer-use 应用访问授权超时，因此本轮未完成真实鼠标点击、Esc、Alt-Tab 的交互验收，不能将键盘回放当作鼠标锁定的实测证明。

## AI CLI 与 AI Runtime 的范围

- 开发期 AI CLI：指处理需求、项目/场景/组件制作、资产流程、脚本、构建与验证的开发代理。本示例目前只接通模型调用、受限参数生成以及部分自动化制作和验证工具；完整生命周期尚未交由本地模型编排。
- 运行期 AI Runtime：独立游戏通过异步 LLM 调用获得参数，经严格校验后由 Lua 发布到组件，改变后续新局的棋盘尺寸、雷数和主题。并未让模型执行任意代码或实时替代扫雷规则。
- 实测模型是本地 Qwen3.5 0.8B；OpenAI、Anthropic、Gemini、Ollama 是四种接口适配，并非四家模型分别参与开发。
