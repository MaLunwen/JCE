# 能力是否真正运行

声明、菜单、依赖或通过单元测试，不能证明功能已被出货应用使用。应分类能力状态，并引用真实定义和调用点。

| 状态 | 证据 |
| --- | --- |
| absent | 检索公开头、实现和消费端，均未找到支持路径 |
| header-only | 存在公开声明，没有可用实现 |
| stub | 实现返回占位结果，或未实际执行便报告成功 |
| implemented-unwired | 实现可用，产品代码没有调用 |
| wired-editor-only | 编辑器有调用，出货运行时没有调用 |
| shipped | 所需产品路径在被测构建变体中确实执行 |

判定不存在前，检索公开伞头、组件注册、实现、编辑器、语言绑定及对应示例项目。内部实现说明机制已存在，即使消费端 API 尚未公开。

```bash
rg --files engine/include/jce
rg -n 'jce_runtime_create|jce_runtime_step' engine/src editor/src examples scripting
```

分别统计定义、声明、注释、测试及产品调用。tests/ 已入库，但测试调用仍不能证明产品接线。检查目标 release/dist 变体的编译开关和配置。

同时涵盖编辑器与出货运行时的结论，必须验证两端。先证明相关路径执行，再判断结果质量。历史计数和旧截图需依据当前源码重测。使用具体仓库路径；省略号是文字示意，不能作为路径存在的证据。

字体与植被验收应覆盖首次使用、缺失后补入、VFS切换、资产编辑与销毁。
Canvas资源代次归resources.c所有；未被观察到的同路径替换需要显式公共失效通知。
草的当前准备和完整caster集合必须先于阴影缓存验收；缓存非空不证明当前请求
已经成功准备或绘制。颜色与深度的形变要在真实后端对比。CPU失败原因或trace
回执与实际像素结果必须区分，保留两者证据并记录当前缺口。

项目自定义资产根目录必须经现有 manifest 所有者传到渲染设置、资源解析和
打包器；只测默认 resources/assets 会漏掉实际编辑器消费断链。
Terrain 的公共 32 字节顶点与 Mesh 的 48 字节顶点是不同契约，必须显式转换后
创建网格，处理临时分配失败与释放，不能指针强转。在同一当前原生场景中操作
可见性、投影开关及 Undo/Redo，再核对 GPU 输出。修复前截图和 CPU 转换通过
不代表修复后的像素通过。进程工作集、分配器所有字节与 GPU 字节分别计量。

后端 owned 句柄创建前须显式设为无效值，包括延迟创建的资源；bgfx 的 0 是合法
句柄。测试从未准备延迟资源的冷场景，销毁后在后端退出前核对纹理和 framebuffer
基线。通过现有共享回调记录后端 fatal，并严格断言 fatal 为零；诊断被接收不能
把无效释放变成成功。uniform 对称释放与纹理所有权分别检查。编辑器初始化失败
出口须释放此前已经获取的全部 owner，包括 Canvas，并清空已销毁句柄以支持
重复清理。

读回取消是逻辑状态，不代表后端对缓冲的借用已经完成。重复 cancel/release
须保留 CPU 存储直到提交的 ready frame 或后端 join；关闭时先 retire GPU owner，
join 后再释放保留的 CPU 存储，并让下一会话回到空闲。回调向 host 的通知采用
原子读取并清零，不能假设 fatal 必然重复来弥补丢失事件。计数交错控制与
Noop 资源基线仍须和真实硬件/GPU 完成证据分别记录。

FoliageCluster 的 transient 提交保持整簇准入：容量不足、分配指针为空或分配数量不足时，在复制前拒绝。Trace 保留 requested、实际提交、rejected、reason 及 owner/view/entity；每个 renderer 的有界原因位集抑制重复 WARN。CPU 缓冲准备、命令提交与 GPU/像素验收分别记录。Shader/cache 与显式 alpha-mask 回退仍须单独可观测，transient 控制不能证明这些更早的路径。

模型回调所有权遵循 JceSceneRendererCallbacks.load_model：成功返回独立拥有的
模型并转移给请求它的场景/拾取缓存，不能返回共享借用对象。当前编辑器回调
消费预解码 CPU 结果，或从文件字节新建模型；缓存失效和销毁负责释放这些结果。
拾取 pass 只在当前 ID 渲染中借用场景渲染器结果，下次请求重新解析；独立回退
拥有自己的加载结果。当前回调模式模型 GPU 字节未计费、VRAM 预算驱逐被禁用，
这是现有策略，不能据此推断模型被借用。has_cbs、GPU 字节查询返回零或过时
注释都不证明借用关系或物理驻留。缓存恢复 CPU 控制仍需在声明的宿主中验证
实际 shader/模型与像素结果。

编辑器 Scene View 与 Game View 使用同一 SceneRenderer、不同 view base。
相机 prepass MRT 由私有四视图缓存拥有，每次渲染只借用当前句柄。同一视图、
尺寸和布局的交替请求须保留句柄；resize 只替换该视图。替换或 LRU 驱逐前必须
完整创建候选目标。失败只释放候选、保留原所有权并拒绝当前 prepass；reset 和
destroy 对每组常驻目标只 retire 一次。CPU span 与关联 owner/view/handle/
generation 计数证明请求和逻辑所有权。计数端口与 Noop 基线不证明 GPU 完成、
像素或 Copy 性能成因。SSAO/SSR/TAA/water/SSGI/planar 消费者关闭时，此路径
不能解释该场景观测到的 Copy 使用率。

探针产物须独立验证容器字段、面与 mip 顺序及辐射亮度。半浮点目标或 HDR 文件名
不证明线性输出：gamma/抖动可以保留方向及大于一的值，同时改变实际亮度。
修复前后保留已知自发光标记和同一数值判据。固定 writer 的精确旧格式头约定与
标准 KTX1 typed 字段分开记录；兼容旧文件读取不证明外部工具兼容。适配自有
桥接输出，保留上游字节。未版本化的公共配置不能假设旧二进制 padding 为零而
追加开关；优先采用 ABI 兼容、逐次调用所有权明确的入口。

### 场景模型准备与驻留

`jce_scene_renderer_prepare_resources` 的成功返回表示本次准备或轮询已接纳。
`model_cache_count` 统计已驻留模型；`get_model` 返回空指针时，不能区分未请求、
等待处理和失败。分别核验项目必需的模型闭包，以及实际接纳、解码、上传和退出
释放。通用 AssetManager 状态属于该管理器；SceneRenderer 内置模型缓存由另一个
所有者管理。编辑器加载回调与内置异步加载器可能采用不同准备策略；对比冷启动时
需明确记录这一边界。
