# Caged Kingdom 1.0 — Code Agent 完整实施任务书

> **目标**：从 2026-09-01 到 2027-01-29，完整实现、测试并发布本套规划定义的 Caged Kingdom 1.0。  
> **性质**：必须实际修改代码、数据、场景、测试和构建，不能只输出建议或报告。  
> **长期设定**：以 `CK_SETTING_BIBLE_v1.1.md` 为世界观权威。  
> **首发范围**：以本套 CK 1.0 文档为生产权威。

## 1. 强制执行

Code Agent 必须持续推进，直到：

- 所有 R0 已完成；
- 所有 R1 已完成或由用户明确批准降级；
- 全部主线、支线、活动和结局通过；
- 资产和 Prefab 完成或使用正式合法替代；
- 独立清洁环境验证完成；
- 发布验收通过。

不得在以下状态结束：

- 只搭灰盒；
- 只实现系统但没有任务；
- 只做任务但资产未进正式管线；
- 只运行单元测试；
- 只在开发机可运行；
- 用占位资产冒充正式完成；
- P0/P1 未清零；
- 未独立验证；
- 未完成存档和发布 Build。

## 2. 允许暂停的唯一情况

### 完整完成

全部验收通过。

### 外部阻塞

例如：

- 必要商业资产授权未获得；
- 商店账号或签名凭据缺失；
- 指定硬件完全不可获得；
- 用户必须决定的故事或内容冲突；
- 外部平台审核拒绝且需要用户资料。

发生阻塞时：

- 完成不受影响的所有工作；
- 提供证据；
- 提出具体问题；
- 给出推荐方案；
- 明确获得答复后从哪一步继续。

普通编译错误、测试失败、代码复杂和制作量大均不是暂停理由。

## 3. 开工前必须确认的问题

仅在仓库无法确定时集中询问：

1. 发布平台是否仅 Windows/Steam；
2. 是否有 Steam AppID；
3. 目标最低配置；
4. 是否允许采购商业动画、模型和音乐；
5. 资产预算；
6. `BagMan.glb`、`chalet.obj`、音乐等现有资产的 License；
7. 中文/英文是否同时首发；
8. 是否允许合法商业 TTS；
9. 是否必须在 2027-01-29 发布，还是允许 1 月内其他日期；
10. 是否允许取消 R1 内容以保发布日期。

没有阻塞时不要反复询问普通实现细节。

## 4. 需求追踪

创建：

```text
caged_kingdom/docs/production/
├── REQUIREMENTS_MATRIX.md
├── GAMEPLAY_STATUS.md
├── MISSION_STATUS.md
├── ASSET_STATUS.md
├── BUG_STATUS.md
├── PERFORMANCE_STATUS.md
└── RELEASE_ACCEPTANCE.md
```

每个需求记录 ID、文档、代码/场景、资产、测试、状态、阻塞、证据和 Commit。

状态仅允许：

- PASS；
- FAIL；
- BLOCKED_EXTERNAL；
- NOT_APPLICABLE_APPROVED。

不得使用“基本完成”。

- Renderer；
- ECS；

- Audio；

- Input；
- Save；
- World Streaming；
- Mission Framework；

## 7. 测试要求

每个功能必须具备：

1. 单元测试；
2. 集成测试；
3. 场景测试；
4. 存档恢复；
5. 键鼠和手柄；
6. Low/Release；
7. 错误路径；
8. 独立验证。

每个任务必须验证正常、失败、重试、保存、加载、对话跳过、目标提前死亡、载具损坏和流式切换。

## 8. 独立验证

实施完成后：

- 新 Worktree；
- 清理 Build；
- 重新 Conan/CMake；
- 不使用开发者临时文件；
- 新用户配置；
- 新存档；
- 从 M01 通关到两个结局；
- 运行自动测试；
- 运行性能；
- 运行离线；
- 运行无 AI；
- 安装包测试。

独立验证不能只运行开发阶段相同的单元测试。

## 9. 资产规则

缺少正式资产时可以用占位完成玩法，但不能把占位视为最终完成；必须记录替换任务。Release Acceptance 前所有 R0 占位必须替换，R1 占位只有用户明确批准才能保留。外部资产必须记录 License。

## 10. 范围保护

2026-11-30 后禁止新增：

- 系统；
- 区域；
- Boss；
- 主线；
- 载具类；
- 武器类。

新需求只能替换旧需求、修复质量、降低风险或获得用户批准。
